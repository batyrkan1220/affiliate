# Teliks: кабинет вебмастера (бэкенд Offer18)

Affiliate-кабинет для блогеров и таргетологов. Все данные берутся из Offer18 API: офферы, статистика, конверсии, трекинг-ссылки. Регистрация и вход тоже проходят через Offer18 API.

## Как это устроено

```
Браузер ──► этот сервер (Node/Express) ──► api.offer18.com
            • сетевые ключи Offer18 хранятся только здесь (.env)
            • каждый запрос ограничен ID вошедшего вебмастера
            • цены advertiser, другие вебмастеры, URL advertiser и приватные заметки в браузер не попадают
```

Токены Offer18 (MID, API key, Secret key) вводит **только администратор** в файле `.env` на сервере. Вебмастер никаких токенов и API-ключей не вводит и не видит.

| Раздел кабинета | Endpoint Offer18 |
|---|---|
| Регистрация | `POST /api/m/affiliate` (action=create) |
| Вход | `POST /api/m/affiliate_login` |
| Офферы, трекинг-ссылка | `GET /api/m/offers` (личная ссылка берётся из карты affiliates) |
| Дашборд, статистика, конверсии | `GET /api/m/report` (с фильтром `affiliate=<ID>`) |

### Заявка на доступ к офферу

Оффер, к которому у вебмастера пока нет доступа, можно запросить кнопкой в кабинете. Заявка **не уходит в Offer18**: она сохраняется локально в `data/access-requests.json` (путь меняется переменной `REQUESTS_FILE`). Вебмастер до одобрения видит оффер со статусом «Заявка отправлена».

Порядок действий администратора:

1. Посмотреть заявки: `npm run requests` (показывает ожидающие заявки, сгруппированные по офферам; `--all` покажет и выполненные).
2. Назначить вебмастера на оффер в панели Offer18: **Offer → Assign Affiliates**.
3. Отметить заявку выполненной: `npm run requests -- --done <id>` (достаточно первых символов ID).

## Запуск

```bash
npm install
npm run demo          # без ключей: http://localhost:3000, вход demo@example.com / demo1234
```

Боевой режим:

```bash
cp .env.example .env  # администратор заполняет O18_MID, O18_API_KEY, O18_SECRET_KEY, SESSION_SECRET
npm run check:offer18 # проверяет ключи и формат ответов Offer18
npm run check:offer18 -- 1234   # то же + проверка статистики вебмастера с ID 1234
npm start
```

**Сначала запустите `check:offer18`.** Формат тела запросов регистрации и входа (form или JSON) в документации Offer18 указан не полностью. По умолчанию используется form. Если Offer18 возвращает ошибку на регистрацию или вход, задайте в `.env` `O18_BODY_FORMAT=json` и проверьте снова.

## Команды

| Команда | Что делает |
|---|---|
| `npm install` | установка зависимостей |
| `npm run demo` | запуск на демо-данных, ключи Offer18 не нужны |
| `npm start` | запуск с боевыми данными Offer18 |
| `npm run check:offer18` | проверка подключения к Offer18 (секреты не выводятся) |
| `npm run requests` | список заявок вебмастеров на офферы |

## Ограничения

- **Выплаты, баланс, инвойсы** в открытом API Offer18 отсутствуют. «Доход» в кабинете — это сумма подтверждённых и ожидающих конверсий. Фактические выплаты проводит сеть.
- **Настройки postback и восстановление пароля** пока не реализованы. Восстановление пароля через API Offer18 возвращает новый пароль серверу, а его отправка на почту требует подключения SMTP.
- **Статистика** собирается на сервере из строк отчёта Offer18 и кэшируется на 60 секунд. Максимальный период выборки — 92 дня. Если данных слишком много (`REPORT_MAX_ROWS`), интерфейс показывает предупреждение.
- Используется одна валюта (первая валюта из строк отчёта).
- Названия полей ответа Offer18 взяты из документации. На некоторых аккаунтах они могут отличаться. Их приведение к единому виду находится в одном месте: функция `normalize()` в `lib/stats.js`.

## Перед запуском в production

- `SESSION_SECRET` — длинное случайное значение. Сгенерировать: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
- Если сайт работает по HTTPS, задайте `COOKIE_SECURE=1`. Если за nginx, Cloudflare или балансировщиком, задайте `TRUST_PROXY=1`.
- Сессии хранятся в памяти (MemoryStore): при перезапуске они сбрасываются, и при нескольких инстансах не разделяются. Для production подключите Redis-хранилище (`connect-redis`).
- Нужен постоянно работающий Node-процесс: VPS, Render, Railway или Fly. Serverless (например, Vercel) из-за хранения сессий в памяти не подходит.
- Для регистрации добавьте CAPTCHA. Сейчас защита только по IP: не более 5 регистраций в час.
- Если оставить `NEW_AFFILIATE_STATUS=Pending`, каждого нового вебмастера нужно подтверждать вручную.
- Папка `data/` (заявки) должна лежать на постоянном диске, и её нужно регулярно резервировать.
