# Teliks: кабинет партнёра TrendMe

Кабинет для партнёров TrendMe (блогеры, таргетологи, владельцы каналов). У каждого партнёра — своя ссылка на Telegram-бот TrendMe (`https://t.me/Trendmekzbot?start=p_<код>`). Клиент, пришедший по ссылке, закрепляется за партнёром навсегда, и с каждой его оплаты партнёру начисляется процент.

## Как это устроено

```
Браузер ──► этот сервер (Node/Express) ──► Supabase «teliks»   (логины партнёров, реквизиты, заявки на выплату)
                                       └─► trendme.kz/api/partner-api   (переходы, клиенты, оплаты, начисления — по секрету)
```

- **Партнёров создаёт только администратор** в админке TrendMe: «Партнёры» → партнёр → «Кабинет Teliks» → email. Пароль показывается один раз. Самостоятельной регистрации нет.
- Партнёр видит только свои данные: переходы по ссылке, начисления (номер заказа, сумма, %, начисление), баланс. Данные клиентов не передаются.
- **Выплаты:** партнёр указывает реквизиты и отправляет заявку; администратор отмечает её в админке TrendMe («Выплачено» / «Отклонить»). Доступно к выводу = начислено − выплачено − заявки в обработке.

## Запуск

```bash
npm install
npm run demo          # без ключей: http://localhost:3000 (вход: DEMO_EMAIL / DEMO_PASSWORD)
cp .env.example .env  # боевой режим: SUPABASE_*, TRENDME_API_SECRET, SESSION_SECRET
npm start
```

`TRENDME_API_SECRET` здесь и `TELIKS_API_SECRET` в TrendMe — одно и то же значение. В TrendMe также нужны `TELIKS_SUPABASE_URL` и `TELIKS_SUPABASE_SERVICE_ROLE_KEY` (чтобы админ создавал логины и обрабатывал заявки).

## Интерфейс

- Три языка: русский (по умолчанию), казахский, английский.
- Адаптирован под мобильные устройства.

## Перед запуском в production

- `SESSION_SECRET` — длинное случайное значение. Сгенерировать: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
- Если сайт работает по HTTPS, задайте `COOKIE_SECURE=1`. Если за nginx, Cloudflare или балансировщиком, задайте `TRUST_PROXY=1`.
- Сессии хранятся в памяти (MemoryStore): при перезапуске они сбрасываются, и при нескольких инстансах не разделяются. Для production подключите Redis-хранилище (`connect-redis`).
- Нужен постоянно работающий Node-процесс: VPS, Render, Railway или Fly. Serverless (например, Vercel) из-за хранения сессий в памяти не подходит.
